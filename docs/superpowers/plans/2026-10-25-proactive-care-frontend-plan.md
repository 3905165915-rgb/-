# 主动照护清单：前端实施与核验

依据用户提供的《主动照护建议改进清单与比赛视频脚本》，对照前端 8bcc164 与后端参考分支 a6c0a6f。仅修改前端及验收文档；视频脚本作为需求示例，不生成真实老人数据。

## 差异与设计

1. 已有印象报告及通用记忆表单，缺少老人档案中的分类记忆总览。新增共享总览，区分当前习惯、临时意愿、待核实变化、停用与历史；展示来源快照、表达者、确认者、场景、有效期、复核提示和修订历史。专业要求继续走正式照护计划，不纳入生活偏好。
2. 场景提示已经接入有效记忆，但来源信息不足。补充类别、有效期、表达者与来源版本，并防止账号变化、组件卸载后的旧响应回填。
3. 新建任务仍通过人工记录间接生成；当前后端已有 POST /tasks。改用该接口，保留原有持久恢复、提交确认和幂等保护，显式要求班次、责任人、截止时间、完成标准，支持同一老人当前有效记录的来源版本及执行前提。旧的待核实请求必须仍能按原路径重放，不自动迁移。
4. 完成结果仅有自由文本。增加可选的反馈辅助填写，将本人反应、事实与效果判断编入现有 result 字符串；默认效果“尚不能判断”。不把文本记录宣称为结构化效果复核或后续任务安排，不把部分完成提交为已完成。
5. 主动建议实体、采纳/拒绝/一建议一任务、结构化效果复核、后台整理作业及其状态均缺少后端接口。本轮不伪造这些能力，验收记录逐项列明依赖。

## 实施顺序与验证点

- [x] 分类记忆及历史：严格校验老人、类别、状态、日期、证据；临时意愿与长期偏好并存，来源变更明显提示，管理操作复用现有受保护表单。
- [x] 场景提示：保持场景过滤，防止陈旧响应和越账号展示。
- [x] 直接创建任务：对齐现有后端字段；校验来源老人/状态/版本/入住关系、显式时间、班次责任人及前提；验证不再生成虚构观察记录，恢复重试使用同一幂等键。
- [x] 事实反馈：辅助生成现有文本字段，不自动断言效果，不创建未安排的后续任务；草稿仍即时恢复。
- [x] 单元测试、双端类型检查和构建、必要浏览器回归、320px检查、lint与diff检查。
- [x] 差异验收记录：区分前端通过、模拟契约通过、待真实后端联调和后端缺口。不将视频脚本当作已通过的验收证据。

核验结果：574项单元测试、89项浏览器检查通过；两端类型检查、生产构建、演示构建、ESLint错误检查和补丁检查通过。范围与待办见 `docs/主动照护前端差异与验收记录_2026-10-25.md`；不将本轮前端完成等同于清单新增闭环全部完成。
