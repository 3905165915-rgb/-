# 老人记录即时分析、单页交班与时间线设计

**日期：** 2026-10-27
**状态：** 已通过
**范围：** 前端管理端、移动端及后端 API、AI 编排、时间线服务与持久化；前后端分支分别维护和发布。

## 目标

1. 在老人档案中恢复并整合文字、语音转写和照片辅助观察。提交照护记录后，AI 在当前页面立即分析场景、观察、任务线索和习惯线索，提交人一次核对结果。
2. 长期习惯不再要求主管二次确认。AI 使用原文里的明确时间和频率表达区分长期模式、近期观察及当次意愿；提交人核对后，明确表达的长期习惯可直接进入已确认照护提示。
3. 将交班压缩为一个页面：输入、即时摘要、待办核对和提交在同一处完成。已有未完成任务沿用，避免重复建任务；新提取的任务由提交人一次核对后创建。
4. 统一老人时间线的登记时间语义：由服务器登记时间决定分组、筛选、分页和排序；最新登记事件置顶。实际发生时间（若存在）独立展示，不决定位置。
5. 保留权限隔离、来源追溯、幂等与失败恢复，不因 AI 故障丢失已保存的正式记录或已确认的交班。

## 角色与数据可见性

- 管理员和主管可查看交班明细，包括提交人、提交/接收时间、班次、来源记录与 AI 分析/确认信息。
- 护理员及家属只查看交班摘要和与其权限范围相关的待办；家属内容必须按其已授权老人过滤，不能通过共享交班跨老人泄露资料。
- 老人时间线继续由服务端按当前账号和老人照护范围授权。家庭用户只经既有授权的家属动态查看可公开内容，不获得员工内部交班明细。
- 数据权限由后端强制执行；隐藏前端字段不构成授权。不得返回无权限字段后寄望于 UI 隐藏。

## 记录与 AI 即时分析

### 录入与持久化

- 从老人档案进入时自动固定老人和当前有效入住上下文；提交前显示当前老人、入住、班次及时间，允许在权限范围内核对。
- 支持直接输入文字、语音转写后编辑文字、拍照/选图。沿用现有语音 WAV 格式、最长 60 秒和上传上限，音频不持久化；沿用照片 JPEG/PNG/WebP、单张 4 MiB、安全上传、私有访问及既有视觉审核边界。
- 语音转写结果先由工作人员检查并编辑，只有工作人员提交的文本进入正式记录和 AI 分析。照片是关联依据；未经授权读取的照片不进入提示词。视觉分析只描述可见内容，不诊断或作安全、病情、身份判断。
- 提交时可选择实际发生时间和班次。后端另行生成不可由客户端伪造的 `recorded_at`，并保留显式提交的 `happened_at`。老人、入住、班次、来源媒体、记录和审计事件均由后端校验关联。
- 先保存正式原始记录，再同步触发此次 AI 分析并在同一工作页显示结果。AI 调用不得持有 JSON 写锁。正式记录持久化成功即代表记录成功，不因 AI 超时或不可用撤销。

### 分析与一次确认

- AI 结果须附可验证的来源记录/照片和原文引述；没有可靠依据时明确返回“未发现”或“待观察”，不得编造场景、任务、频率或偏好。
- 结果卡在同页分为：识别场景及其依据/待核对状态、观察摘要、任务建议、习惯/偏好线索及其来源。场景选择和当前已确认的适用照护提示在提交前可见；提交人可修正场景。不把模型自评置信度作为可信度或授权依据。
- 提交人一次确认本次 AI 输出：确认、修改或拒绝各项。确认任务时须检查老人、入住、负责人、班次、截止时间和重复任务；AI 不可补猜缺失责任人或时间，缺项需提交人补齐或留待人工办理。任务沿用已授权的后端创建和审计规则。
- 长期偏好无需主管再次审核。规则依据和分类如下：
  - 原文明确表达重复规律（如“每天”“每周”“经常”）时，AI 可提出长期习惯候选；有权提交该老人记录的员工核对候选及引文后直接写入该老人的已确认提示。该确认由服务端检查当前账号、老人照护范围和记录归属，不依赖前端角色按钮。
  - 必须区分“当事人在本次记录中自述长期规律”（以原文和表达者标记）与“系统从多个独立日期的记录中观察到重复”（以去重后的来源记录、发生/登记日期和引文标记）；不能把单句自述伪装成跨日期的系统观察。
  - 频率词语模糊或原文只表示本次状态时，仅写入近期观察/当次记录，不提升为长期习惯。
  - “今天想休息”“这次不参加”等当次意愿保留于当次记录，不创建长期提示。
  - 记录日期、来源事件和重复引用应参与判断；一条记录、交班摘要或复制引文的多次出现不能被误算成多个独立事件。AI 不把观察到的相关性描述为已证明的因果关系。
- 采用原文快照、来源版本和幂等提交。正式记录保存后若来源修订，旧分析不可确认，应重新分析；同一确认请求重试不得重复创建记录、习惯或任务。
- 若 AI 分析失败，页面明确区分“记录已保存”和“分析未完成”，保留原记录 ID 和请求上下文，提供对同一记录重新分析/重试；不可重复创建正式记录。分析重试失败仍可查看原文并手工办理。
- 新流程不得创建记录后台分析队列。切换上线时停止旧记录分析 worker；将旧 `care_jobs` 中仍处于 queued/processing 的作业标记为可见的“需当场重新分析”失败状态并保留作业、记录、来源和错误原因，用户按原记录 ID 在前台重试。已完成作业及其他集合数据保留；计划排期 worker 与记录分析独立，不因该变更停用。

## 单页交班

### 办理路径

- 护理员从移动端“交班”入口进入，也可从当班工作台/待办跳转；老人档案相关上下文自动带入。
- 页面一次显示交出与接入班次、当前未完成任务、需交代的正式记录和一个交班内容输入区。对已有历史事项提供来源与状态概览，不再要求“创建草稿—刷新—独立生成摘要—跳页提交”的多页操作。
- 支持键入或语音转写补充交班内容。转写文本先可编辑；原有班次授权和任务接续规则不变。
- 提交前调用 AI 即时生成交班摘要和结构化事项，在当前页面显示摘要、依据、待办去向及习惯/偏好线索；交班提交人一次核对、修改或不采用，再完成提交。
- 已有未完成任务按原任务 ID 与责任关系接续，更新交班关联但不克隆新任务；接班确认在原有任务状态/接班机制中记录。
- 从交班文字新提取的待办必须由提交人核对一次后创建。每条新待办应有可追溯原文、老人、唯一责任人、班次、截止时间和完成标准，并通过权限、范围、状态和重复检查；信息不足时提示补齐或留待主管办理，不猜填、不自动创建含糊任务。
- AI 提取的习惯线索遵从记录频率规则。提交人确认明确长期模式时可直接写入正式老人提示；不明确/当次意愿只作为近期观察。显示来源日期和原文。

### 时间、明细与故障

- 服务器保留不可变/可审计的 `created_at`、`submitted_at`、`submitted_by`、`received_at`、接收人、源/目标班次、关联事项、来源版本、分析版本、人工更改及确认人；权限允许时按原项目规则保留审计事件。
- 管理员和主管可查看完整交班数据。护理员和家属仅能读取摘要及获授权范围内的待办；明细 API 必须按角色裁剪并做后端访问控制。
- AI 服务失败时保留交班输入为当前流程草稿，支持重试分析/编辑，不显示已提交成功；不会丢失未完成任务或自动关闭班次。完成 AI 核对并提交后，若响应未知，按原幂等键查询/重试，不重复交班或派任务。
- 多老人班次按老人授权范围分隔摘要、任务和引用，不能因共享班次把其他老人信息暴露给家属或无关护理员。

## 老人时间线

- 以服务端审计事件的登记时间为唯一主要时间 `recorded_at`；该时间来自服务器写入的 `audit_logs.created_at`/对应持久化创建时间，客户端不得提供或覆盖。
- 如果来源明确记录了实际发生时间，单独返回 `happened_at` 并在界面标为“实际发生”；其缺失时只显示“登记时间”。不把登记时间冒充实际发生时间。
- 依据 `recorded_at` 日期分组；组和组内事件均按最新登记在前。日期筛选、总数、分页游标和稳定并列排序统一使用登记时间及稳定 ID，防止补录旧时间扰乱顺序或分页遗漏/重复。
- 时间线采用可辨识的纵向日期分组，事件类别/状态清楚标记；每项突出标题/摘要、登记时间和操作人。详情按访问权限提供来源记录、任务、评估、计划、交班、习惯变更、安全事件等业务链接和来源依据。
- 详情支持筛选、加载更多和事件回放；不再把所有项目挤成平铺文字。对时间格式异常的旧数据显示“登记时间待核实”，不能静默排序到虚构日期；修复/回填须有服务端可追溯来源。
- 时间线描述系统中登记的事件，不得暗示一条记录或任务状态能独立证明现实服务已经发生。

## 方案与边界

采用“一个老人工作页与两个单页工作流、共用可审计后端服务”的方案。保留现有兼容 API 和附件/语音服务，增补同步分析/确认及基于 `recorded_at` 的时间线契约。数据写入按后端现有单写者 JSON store 模式、事务和幂等约束执行；任何数据结构变化须备份优先并显式迁移。

本设计不授权 AI 作专业评估、诊断、用药/治疗建议、事件定责、修改已完成历史记录或对家属发送未经审核的健康判断。AI 只产出有依据、待人核对的记录结构建议；长期生活习惯的正式提示由提交人对明确频率证据一次核对后确认。线上环境当前为 demo，本设计不改变部署环境级别。

## 验收标准

1. 新记录可从老人页使用文字/语音/照片输入；确认后后台正式记录只生成一次，并保存服务器登记时间、可选实际发生时间、老人/入住/班次关联。
2. AI 输出当场回显场景、摘要、任务和偏好/习惯建议及逐条依据；明确频率词经提交人一次确认成为长期提示；模糊频率成为近期观察；临时意愿保持当次状态。
3. AI 超时/503 不影响已保存记录；重试分析复用同一记录，不重复入库、生成任务或记忆。内容修改和权限撤销会阻止旧 AI 结果确认。
4. 无主管二次审核时，只有可提交该老人记录范围内的员工才能确认长期习惯；确认人和时间写入审计。明确频率的单条自述与跨日期观察在界面/持久化中明确区分。
5. 新任务缺责任人/班次/截止等必要条件时不自动猜填、不创建；已有任务/同事件的重复引用不产生重复事项。
6. 交班在一个页面完成录入、即时 AI 分析、核对和提交；既有未完成任务沿用原 ID，AI 新提取任务经提交人一次确认才创建。
7. 管理员/主管能查看完整交班明细和服务器记录的提交/接收时间；护理员/家属 API 响应不包含这些明细或无权限老人数据，只包含授权摘要及待办。
8. 时间线按服务器登记时间倒序分组、筛选和分页；实际发生时间独立标示。补录旧事件不会改变登记顺序，分页边界无重复/遗漏，过滤和明细都遵从角色范围。
9. 旧版本数据和既有照片、语音、记忆、交班、任务和时间线入口仍兼容；原账号/业务数据保留。若需 schema 变化，隔离演练及恢复验证通过后方可上线。
10. 后端权限/去重/频率分类/重试和并发测试、前端单页与狭屏测试、合成数据浏览器闭环及生产构建通过。不得将合成 AI 结果冒称真实模型效果或实际照护效果。
