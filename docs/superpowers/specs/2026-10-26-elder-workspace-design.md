# 老人工作页与后台整理

本次用户明确授权同时修改前后端、分别推送现有分支并部署，批准详细老人中心设计；随后确认缺项评估可保存待补充。沿用 JSON 单进程事务、现有鉴权与证据服务，不改造为数据库。

- 工作入口围绕老人：今日照护、了解这位老人、记录、评估与安排。
- 正式记录先提交成功；同事务创建可恢复作业，模型在写锁外处理。普通无个性化/跟进线索的记录不调用模型。相关记录仅整理当前入住最近30条，排除交班/摘要重复事件，标明覆盖范围。
- 已确认信息和近期观察独立展示。近期观察不作为正式要求；趋势经主管一次采用创建正式提示，临时意愿和专业关注不能由该动作升级为长期偏好。
- 评估逐项中文选项，AI仅提议有原文的答案；上次结果待本次核实。缺项保存为 pending_observation，total_score=null，不允许确认、定级或作为计划依据；现场观察保留人和时间。
- 普通跟进仅在主管授权规则下，由后端核对原文、明确时刻、唯一人员、实际班次、范围及重复后创建。药物、治疗、条件含糊事项不自动执行。
- 已批准计划仅在明确授权的实际班次与原计划版本生成任务；版本或依据变化停止排期，不自动修改安排。
- 前后端各自测试和提交。部署需保留私有配置及数据，显式schema8迁移和备份；缺少服务器认证不得宣称上线。

验收包括跨老人/角色/撤权、原文更正、版本冲突、重复保存/队列重试、未知提交回执、缺项评估和闭环反馈。自动整理不证明实际照护效果。
