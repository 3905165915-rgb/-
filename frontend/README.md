# 护老智交前端

前端采用 pnpm workspace，包含管理网站和移动端两个 Vite 应用。接口请求集中在 `packages/api-client`，业务状态枚举集中在 `packages/shared`。

## 启动

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev:admin
pnpm dev:mobile
```

默认从 `VITE_API_BASE_URL` 读取后端地址，复制 `.env.example` 为 `.env` 后按需修改。移动端先以 Web 模式启动；具备 Android SDK 后再运行 `pnpm cap:sync` 和 `pnpm cap:android`。

默认 `VITE_APP_MODE=api`，接口不可用时只显示错误，不会自动进入演示。权限校验、AI确认入库和业务状态流转仍以后端为准。

### 服务器正式发布

运行 `pnpm build:deploy`，将 `apps/admin-web/dist` 发布到网站根路径，将 `apps/mobile/dist` 发布到 `/mobile/`。发布时使用 `VITE_APP_MODE=api`、`VITE_API_BASE_URL=/api/v1`、`VITE_SAME_ORIGIN_DEMO=false`。专用命令会设置两端不同的资源和路由基址，避免手机端错误加载根路径资源。普通 `pnpm build` 仍适合将单个应用发布到根路径，不用于这个双端共域部署。

## 同源双端演示

```bash
pnpm dev:demo
```

打开 `http://127.0.0.1:5175/admin/` 和 `http://127.0.0.1:5175/mobile/`。必须在同一浏览器的普通窗口中访问相同域名和端口；不支持跨设备同步。不要混用 localhost 和 127.0.0.1。每个标签页单独选择演示角色，登录身份互不覆盖；演示数据通过 IndexedDB 事务共享。

移动端使用护理员身份，在快速记录中点“使用演示原文”，提取、核对并确认。后续可在交班页提交延续事项，在另一护理员标签页接收，在任务详情填写完成结果，主管通过事项编号查看全过程。任意输入可保存本机；预置 AI 只匹配指定示例原文，其他输入应使用手工录入。

主管可在管理端“演示保障”重置数据。重置只清理演示业务和演示草稿，不清理正式模式草稿；重置前的编辑器必须重新创建，不能继续提交。浏览器存储用于本机恢复，不是云端备份，不适合保存真实老人敏感信息。

生产静态演示：`pnpm build:demo`，再运行 `pnpm preview:demo`。部署至静态服务器时，将 `/admin/*` 和 `/mobile/*` 的 HTML 导航分别回退到各自 `index.html`，不能将资源请求回退为 HTML。

## 页面入口

- 管理端：工作台、老人档案、入住与床位、评估、照护计划、每日任务、质检台、双向核对、变化简报、家属沟通、过程回放、演示保障。
- 移动端：护理员工作台、快速记录、AI草稿人工确认、接班、家属动态、过程回放。
- 演示数据：305床王阿姨案例；可在管理端“演示保障”中重置，所有内容带演示标识。

## 与接口的边界

`packages/api-client` 保留已声明的登录、老人、记录提取/确认、任务完成、交班查询/接收、事项回放和家属诉求接口，不新增后端路径。正式模式未接入的人工记录、任务开始/未执行/转交、附件上传、交班提交等只保存本机或禁用；接班对象契约未核实，目前仅只读预览。HTTP成功不等于业务结果已核实，结果不确定时保留草稿且不自动重试。

账号凭证只写 sessionStorage；前端角色路由与菜单是界面限制，不替代后端授权。无角色或未知角色不能进入业务页。清理浏览器站点数据会删除草稿、附件和演示数据。

## 本机恢复与列表操作

任务和交班输入先同步保存文字恢复日志，再异步保存 IndexedDB。页面刷新、同一路由切班与前进后退都保留当前草稿；交班自动保存不追加历史版本，只有“保存新版本”才生成版本。不同文档使用独立日志标识，发生版本冲突时保留内容，提供载入已保存版本或另存独立草稿。

任务附件按每次选择的独立编号关联已落盘的文件，未完成保存的附件会提示重新选择，不以同名旧文件替代。提交阶段及保护记录跨刷新保留，结果待核实时不能重复提交。结束状态、未知状态、当前查询失败时禁止相关提交，但仍可保存本机内容。

两端“本机草稿”支持搜索、类型/状态筛选、逐条或选择删除，显示保存时间、附件数量与估算容量。待核实项目受保护；删除不清除提交锁。存在未选择的恢复分支、删除期间发生新编辑或演示重置时，会拒绝旧删除操作。删除标记只保存恢复日志的 SHA-256 指纹，不保留已删原文；删除检查后晚到的新文字保留为独立恢复分支，不自动覆盖或重建原草稿。

任务列表支持当前已载入数据的搜索、截止时间排序、重置与URL筛选恢复；管理端每页25项，移动端每批30项。交班事项可按老人、来源班次、责任人和已选项筛选，隐藏项仍保留勾选。以上均非服务器全量检索。

接口读取使用字段、枚举、日期和重复编号校验，错误不会自动回退演示数据。状态文案由共享字典提供，未知状态显示“状态待核实”，并禁止状态不明时的写操作。管理端通过 `build/admin-element-plus.ts` 对 Vue 编译输出进行定向解析，实现 Element Plus 组件及官方依赖样式按需加载；独立构建与双端演示共用配置。

## 界面规范

两端共用 `packages/shared/src/ui/theme.css` 的医疗工具风配色，列表和表单使用实色，导航、弹层及固定操作栏使用有限的毛玻璃效果。账号菜单中的“降低透明度”即时应用并单独保存在本机；浏览器不支持模糊或系统要求降低透明度时使用实色，系统降低动效时关闭过渡。

移动端填写页面隐藏全局底部导航，保留返回入口、保存状态和固定主操作；任务按床位、姓名、状态和期限分层排列。管理端采用分组侧栏、紧凑工具栏、白色数据区和任务抽屉。统计仅针对已载入数据，虚构演示、正式提交与本机保存分别标明。界面图标按组件从 `lucide-vue-next` 引入，不替换既有 Vant / Element Plus。

## 验证

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm build:demo
pnpm exec playwright install chromium
pnpm test:e2e
pnpm test:ui
```

浏览器测试需要先启动 `pnpm dev:demo`，默认地址为 `http://127.0.0.1:5175`，可通过 `DEMO_URL` 覆盖。测试使用真实浏览器的 IndexedDB，不依赖模拟存储。可选 `API_ADMIN_URL`、`API_MOBILE_URL` 指向正式模式本地服务，以请求拦截验证500/401/403和写请求不确定性；无需真实后端。已有 Edge 可设置 `BROWSER_CHANNEL=msedge`，不下载额外浏览器。截图与结果默认写入 `test-results/`。

`pnpm test:e2e` 顺序执行原业务链和第二轮恢复/并发/列表回归；`PREVIEW_URL` 可指向 demo 生产预览以检查双端深层地址。测试仅使用临时浏览器上下文和虚构数据。浏览器清空站点数据、设备故障和跨设备编辑不属于本机恢复保证范围；精确提交归属与跨设备去重仍依赖后端。

`pnpm test:ui` 检查320/390/430px移动端、1024/1280/1440px管理端、弹层关闭、固定操作栏、筛选空结果、透明度偏好和降低动效，并将截图写入 `test-results/ui/`（可用 `UI_OUTPUT` 指定位置）。键盘遮挡计算有单元测试，仍需在实际Android设备上验证软键盘、安全区及附件选择器。

项目固定使用pnpm 9.15.5。全局pnpm版本不一致且无法使用corepack时，可用 `pnpm dlx pnpm@9.15.5 dev:demo` 启动；不要混用不同大版本重建已有依赖目录。
