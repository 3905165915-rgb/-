# 护理员交班页修复与验收

## 变化

- 交班页员工读取改用护理员有权访问的 `/staff` 简要接口，避免管理目录 403 导致整个页面数据载入失败。
- 根据本人开放班次、当前时刻和班次顺序选交出/接入班；保留合法历史补交班草稿，修复错误远期班次组合并保留文字。
- 没有后续班次或尚未选班时显示中文原因，不再只有无法点击的按钮。草稿可更换班次并保留文字，提交后可开始下一次交班。
- 原未完成任务按实际班次筛选，显示老人姓名、责任人和中文状态，不显示内部编号，也不混入其他班次任务。
- 分析前刷新交班来源。分析结果允许核对；修改原文后须重新分析或人工核对，不能误交旧摘要。
- 云端失败保留文字，可通过“人工核对交班 → 核对并提交交班”办理，提交标记为人工内容，不伪装为模型输出。
- 已勾选新待办信息不完整时阻止提交，避免静默丢失；新待办截止时间明确按北京时间上传，避免随浏览器时区漂移。
- 提交后的班次名称仍可见；提交期间和已提交内容不可误编辑。版本、来源和后端权限校验继续保留。

## 验收

- 全量单元 66 个文件、766 passed（新增 8 项班次选择用例）。两端类型检查通过，ESLint 无错误但有既有风格警告，正式 API 模式部署构建通过。
- `e2e/handover-quick.mjs`：远期班次倒序、旧草稿恢复、中文任务及准确班次筛选、无下一班提示、分析失败转人工、改原文后防旧摘要提交、更换班次保留输入、手机布局。
- `e2e/workflow.mjs` 交班专项：失败重试、刷新恢复、人工补齐新任务、单次提交通过；截止时间显式 +08:00。
- `e2e/handover-real.mjs`：精确部署包加实际本机 FastAPI，验证分析/核对/提交/接班，原任务编号及数量不变；模拟模型不可用后仍可人工正式提交。脚本只允许本机合成账号，拒绝公网数据。
- 标准 Edge E2E 通过。后端 Linux 731 passed、16 skipped；隔离资料真实 DeepSeek Flash 样例通过，不能据此声称模型全场景准确率。

## 人工重试步骤

刷新或用 Ctrl+F5 重新加载后进入护理员交班页；核对交出和接入班次 → 输入交班内容 → 分析并核对 → 核对摘要 → 核对并提交交班。若云端不可用，直接选择“人工核对交班”继续。若是补交之前班次，请手动选择实际交出班次；系统按该班次显示待接续任务。
