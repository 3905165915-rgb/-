# 个人印象交互简化

## 修改范围

- `ElderQuickRecord.vue`：统一为“个人印象建议”，核对时选择“加入个人印象 / 暂不加入”；不再显示重复频率标签或按频率禁用加入操作。原句放在“原文核实”折叠内，人工可编辑确认后的展示特性。
- `ElderUnderstanding.vue`：默认展示“个人特性”，优先使用服务端 `display_summary`；分类资料、原句与核对入口集中在“原文核实与个人印象管理”。不要求工作人员判定长期/临时。
- `personal-profile.ts`：兼容旧接口资料，避免在摘要区域直接显示“王爷爷说：……”；保留时间、否定和条件，来源内容不改写。
- 旧已确认资料需要摘要时调用 `POST /elders/{id}/understanding/summarize`；资料先显示，摘要锁外整理并缓存。失败不删除已确认资料，重新刷新可重试。

## 不变的业务规则

- 喜好需人工确认后加入；候选内容、原文、版本及操作人保留。
- 未获老人访问权限、来源已变更或过期的提交仍然被服务器拒绝。
- 新待办仍需核对真实班次、责任人、时间和完成标准。
- 摘要只改变展示形式，不自动更改评估、照护计划或任务，不增加家属对内部资料的权限。

## 验收

- 单元测试覆盖服务端摘要优先、旧引语兼容、否定及时间保留。
- `e2e/personal-impression.mjs` 仅允许本机隔离资料：三个没有频率词的喜好可分别确认，个人特性默认不复述原句，原文核实可展开查看，护理员手机端正常显示且无横向溢出。
- 完整前端单元测试、两端类型检查、ESLint、部署构建，以及标准 E2E 结果记入同日发布记录。

## 同轮追加：照护变化页面简化

- 将管理端“变化简报与变更核验”合并为“照护变化”。打开页面自动读取，默认是需要处理的事项卡片，不再并排显示两组操作菜单和空表单。
- 保留“需要处理 / 已处理 / 最近变化”三种视图，老人筛选默认为全部；日期自动使用已有的业务时间格式。
- 点击“查看并处理”后自动滚动到单条详情，显示发生了什么、相关任务、当前可办的下一步；选中的事项、版本和证据指纹自动带入既有接口。
- 原文、当前影响、历史和低频检查入口折叠；处理结果仍经原接口校验，必须由另一位负责人完成独立复查，标记动态已读不会完成服务任务。
- 管理端 `/changes` 和 `/workflows/changes` 使用同一页面；相关任务跳转到已有的 `/tasks?task=...` 入口。
- `e2e/care-changes.mjs` 使用本机合成资料，验证自动读取、指派真实接口、下一步切换及手机布局；不向公网创建测试事项。

## 本轮实际检查

- 前端全量单元测试：65 个文件，758 passed；管理端和手机端类型检查、ESLint、正式 API 模式部署构建通过。
- 标准 E2E 通过；个人印象与照护变化两组生产包实际 HTTP 浏览器验收共 6 阶段通过。
- 个人特性不再仅截取前五条；相同展示文字去重，来源记录仍逐条保留在核实区。
- 本机浏览器验收使用独立合成 JSON 数据，无需清理线上老人、记录、任务或账号。
