# 后端本阶段实现与边界

本阶段目标是可验证的护理记录、任务和交接班闭环。用户明确要求不使用数据库，采用单服务器JSON文件，覆盖AGENTS.md中早期SQLAlchemy/Alembic方案。

## 已实现

1. 保留原有登录、老人读取、AI提取、人工确认、任务列表与完成接口。
2. 正式记录查询、手工录入、草稿恢复/放弃、更正留痕，原文不可被更正覆盖。
3. 任务负责人、带时区期限、固定未执行原因、开始/未执行/恢复/转交/取消与重复提交保护。
4. 跨午夜班次、同员工班次重叠校验、交班明细快照及版本校验、双向澄清、逐项接收，任务沿用原编号跨班延续。
5. DeepSeek交班摘要和文本质检建议，结构及逐字引用校验；规则质检可独立使用。结果不自动修改业务，人工确认留痕。
6. 老人/记录/任务/交班关联时间线，AI原文证据、更正与任务变更的审计。
7. JSON schema v1/v2/v3→v4显式迁移（先备份）、锁内备份、停服恢复工具、每日备份timer；账号停用/角色修改即时使旧令牌失效。
8. SenseVoiceSmall云端识别、客户端WAV录音、工作人员鉴权、大小/时长/并发/频率限制、独立手机测试页；转写经人校对后接已有记录接口，不运行本地语音模型。
9. 个性化照护记忆的人工确认基础：候选、确认、复核、修订、停用/驳回；同老人正式记录逐字引用、当前来源版本校验、场景与有效期过滤；来源更正与记忆转待复核在同一JSON事务提交，历史证据不覆盖。观察类不作为偏好下发。接口详见MEMORY_API.md。
10. 上下文AI记录：按老人/场景/实际班次选择当前有效记忆和本人/未分配待办（管理人员可看范围内所有待办），不发送整份档案；新原文事实、个性化候选、历史提醒分开校验。模型调用外锁执行，保存及确认时复查资料。候选经正式记录确认后单独选择、人工填期限、主管确认才生效；来源与AI草稿留痕。新接口见ASSISTANT_API.md，0.3.7已加入有效场景计划检索。
11. 任务采用记忆的版本关系：明确人工采用/撤回，原始内容、确认信息和来源快照不可覆盖；读取时另查当前差异，未结束任务给待核验标志，已结束任务仅保留历史。采用增加任务版本、触发交班草稿刷新，交班条目深拷贝引用，原任务跨班保持关系。AI待办上下文仅接收采用版本的当前检查状态，不注入失效旧内容。见TASK_MEMORY_API.md。
12. 变更影响核验队列：来源更正和记忆变更同事务检测，手动扫描补查自然到期；未关闭单去重、固定初次快照、追加差异观察，主管指派、负责人引用当前正式记录提交、另一位主管复查或退回。定位含该任务的跨班交班条目，历史快照不覆盖。提交/复查校验任务/记忆/交班上下文、证据版本和实际处理状态，关闭不等于服务完成；规则队列不调用AI。见CHANGE_REVIEW_API.md。
13. 0.3.4复查修复：任务完成/流转/调整检查班次开放与成员，已结束完成结果的重复读取不产生新执行；时间线过滤无访问权交班事件；普通AI提取/摘要/质检在调用前及保存时复查账号和原角色，记忆/任务/交班写入增加事务内账号校验。没有新增请求字段或JSON迁移，详见REVIEW.md。
14. 条件待办核验：主管明确标准/指定核验人/提醒期限，指定人引用当前正式记录人工确认满足或未满足，满足须有效期。原任务开始/完成重新检查条件，仍允许未执行/转交/取消等进展记录；跨班同任务保留原核验快照和历史，清空当前责任/结论，再明确认领和核验。来源更正、自然到期联动交班草稿刷新、AI上下文过期检查与规则质检，AI不判定或自动触发。可选字段不改变schema4，见TASK_CONDITION_API.md。
15. 老人/员工/床位与入住流程：老人建档及资料修订、床位增改启停、实际入住/旧在院显式补登记、换床/外出/返院/离院/再次入住。身份不随床位变化，入住单及床位段保留历史；占用与关系核对、版本/幂等/事务回滚防重占。离院先人工处理未结束任务，后续新记录/任务执行受状态限制，AI生成及确认复查照护状态。员工分级管理、安全目录、停用前责任交接、密码重置及会话版本防旧令牌复活。仍为schema4，不偷偷补写历史；见FACILITY_API.md。
16. 评估与照护计划首版：Barthel基础计分演示模板、人工来源/观察时间/复评期限、主管确认并填写机构档位依据；新评估及新计划替代保留前版。计划审批后按日历日期/周期/实际班次显式生成去重待办；旧待办保留计划和评估版本，依据失效阻止开始/完成，取消后明确补发才建立替代任务。交班刷新、规则质检和上下文AI纳入当前计划状态，不自动认定护理等级或实际执行；schema4，见PLANNING_API.md。

技术路线：FastAPI → 路由鉴权与请求校验 → 业务状态机 → 文件锁事务/原子替换 → JSON；外部AI请求在锁外执行，保存前重新检查数据版本。数据更新失败不提交半条记录。

## AI参与范围

| 环节 | AI职责 | 程序约束与人工动作 |
|---|---|---|
| 记录提取 | 从护理员原文提取观察和候选待办，保留条件/否定 | 严格结构、原文逐字片段、候选证据校验；人工编辑确认后建正式记录/任务 |
| 上下文记录 | 原文提取个性化候选，结合有效记忆、当前场景已审批计划与待办给带引用的历史提醒 | 历史信息和计划不是本次观察；双重版本检查、时效及范围过滤；正式记录确认与记忆确认分开；引用校验不保证语义正确 |
| 交班摘要 | 整理已有正式记录和未完成任务，给出引用 | 检查source_id及quote；资料变化丢弃结果；人工提交才生效 |
| 质检建议 | 提示可能的文本矛盾、否定丢失、条件不明 | 不作医疗/责任判断；建议附引用，管理人员确认/不适用并说明 |
| 规则质检 | 不用AI，按确定规则找流程缺口 | 负责人/时间/逾期/草稿/交班覆盖，避免全部问题依赖大模型 |

这套实现验证了流程约束和证据关联，不证明模型具备医学判断能力。校验引用存在也不保证解读正确，尤其涉及否定与条件时必须由人核对。Mock仅作明确标注的本地演示，云端配置禁用自动Mock降级。

## 不属于本阶段的功能

- 拒绝次数触发复核；仍待后续实施。上下文接口已加入记忆和有效计划，普通旧extract接口不自动注入历史。
- 照护计划变更的独立整改/复查工单；已有计划任务执行拦截、原始快照、规则质检和明确补发，但change_reviews仍只覆盖任务采用记忆。未包含自动定时扫描/消息推送。家属身份和授权由主管线下核实并录入凭证，不对接实名核验；已有反馈，但不自动从家属自由文本判定任务条件满足。
- 收费/押金/合同/结算和任意回填历史入住；本阶段仅做入住状态及床位关系，不等同全部机构入院手续。旧数据关联矛盾没有强制覆盖接口，须备份核查。
- GB/T 42195完整综合评估、其他风险量表、本地护理等级/收费/补贴自动映射、定时自动生成清单。当前只是Barthel计分演示配置和人工机构档位，不声称符合全部机构评估要求。
- 有法律效力的电子签名、知情同意全流程、约束具、证照到期、完整收费经营分析。
- 未生成计划服务的应履约台账、历史时点统计回放、公开案例的专业脱敏审查；本版导出默认最少字段及临时ID映射，不承诺完全匿名。
- 前端分支语音按钮联调、长录音和流式识别、普通话/方言/专业词系统评测。
- 前端新增业务联调、原生APK。

## 演示适用性

适合单机构虚构数据、小规模演示。当前权限是角色/作者/任务负责人/班次层，不是完整多租户或逐老人授权。JSON历史、幂等响应与备份会持续增长，正式生产前须补齐容量治理、异地备份、请求限流、细化授权和完整数据保护。当前未宣称支持多机构生产部署。

自动备份保存在同一服务器，可应对误操作，不能抵御整机或磁盘丢失。恢复工具保留当前账号及密码散列，恢复前另备份当前业务数据；0.4.0恢复时作废旧登录和缓存，并撤销恢复快照中的有效家属绑定，防止旧授权复活。跨版本恢复先在副本迁移验证。
