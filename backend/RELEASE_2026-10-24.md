# 2026-10-24 后端累积更新与验收

## 本次交付

代码范围为 `backend/`，独立提交到 `feat/backend`。运行方式仍为 FastAPI + 单服务器 JSON 存储，无数据库。JSON 版本为 5；本次部署不迁移、不重置、不重新生成线上数据，不更换账号、密钥或服务配置。

### 1. 个性化照护：印象进入实际工作

- 老人印象只读取该老人当前已确认或已更正的观察记录，分批整理并核验逐字引用，保留来源版本、发生时间、录入时间、模拟标记和覆盖范围。
- 模型总结保持候选状态。主管逐条核对后，还须明确选择“加入照护记忆”，填写适用场景、本人／家属／工作人员表达、依据和原因，才成为正式生活提示。
- 新增 `POST /api/v1/elders/{elder_id}/impressions/{report_id}/points/{point_id}/activate-memory`。管理员／主管有权操作，护理员和家属无权确认。支持请求幂等和业务去重。
- 仅当前、未到复核期、来源未变的已核对长期趋势允许加入。临时意愿、冲突、单次观察和需要专业判断的关注项不直接转为长期偏好。
- 不自动生成任务、不改照护计划、不自动执行专业照护。主管仍需核实适用性；引用准确不等于总结含义一定正确。
- 原始印象关联独立保留，人工修订记忆来源后，旧印象仍显示已关联；重复提交不再创建第二条记忆，也不自动重新确认修订后的候选。
- 对应场景提示及上下文助手读取已确认有效记忆，无须重新调用模型。明确引用的任一记录被更正、撤回或批准状态变化时，该记忆退出有效上下文并进入复核；仅到建议复核日期不一律让偏好失效。

### 2. 一并上传的前期改动

- 独立新建任务、来源任务校验与幂等提交；班次成员及管理角色的服务端校验。
- 上下文整理、待核对草稿人工编辑及版本记录；AI 失败保留原文，人工登记可继续。
- 正式记录更正先预览直接引用的记忆、任务、交班事项和家属摘要，再按预览指纹应用并生成影响核验清单；不重写历史，不把记录缺失判定为漏护。
- 记忆复核生命周期、重复拒绝去重与提醒。连续拒绝只触发复核，不自动更改长期偏好。
- JSON 原子保存和故障保护，错误响应提供安全中文提示。
- 测试脚本的模拟老人采用简短称呼，展示用编号缩短；演示重置和长期记录脚本仅限明确的演示环境，部署时不执行。

## 人工复测

管理员进入“张阿姨 → 老人印象”，核对一条有多日依据的长期偏好，再“加入照护记忆”，选择活动等场景并确认。护理员在新增记录选择同一老人和对应场景，查看无需模型等待的“本次服务提示”。更换服务场景不应残留上一个场景的提示。正式记录保存成功应立即显示服务器回执，后台目录刷新不再延长提交按钮等待。

不良事件是需要工作人员独立上报、分级、整改和复查的事件，不由普通记录自动认定。系统可以提示疑似问题，事实、责任和定级仍需人工核实。
