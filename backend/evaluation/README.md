# AI效果验证准备

本目录8条人工编写合成案例只供开发评测，涵盖否定、条件、临时意愿、转述、多个动作、更正、避免诊断与提示注入。没有真实老人数据；不是独立机构盲测集。不要拿本团队合成集或Mock结果宣传真实AI准确率。

`scripts/evaluate_ai.py --predictions <JSONL> --output <报告JSON>`离线读取原始模型输出，不连厂商、不改存储。每行格式：`{"case_id":"negation","provider":"实际提供方和模型版本","output":{"observations":[...],"task_candidates":[...],"evidence":[...],"warnings":[...]}}`。结构与普通提取接口严格输出一致，任务需有evidence_text，不能写负责人ID/具体执行时间。

报告区分缺失、结构/引文不合法、任务查准查全、限定原文覆盖。补交重复/未知ID拒绝。任务匹配用人工指定的原文锚点和条件文本，属于可复现的近似评分；整句照抄能提高覆盖率，不等于提取质量高。报告不自动证明标题语义、否定作用域、归因或医学正确性，必须人工补审。

条件比较只允许忽略开头的“如果”二字，其余前提必须完全一致；不采用模糊语义评分。遗漏整个条件、主体、“仍”等限定词、改动否定或把纯时间作为前提，均不能匹配。原文逐字引用校验先于评分执行。报告中的`vendor_calls_by_evaluator=0`只指离线评分器自身不联网，不表示输入预测来自Mock。

## 真实接口验收

2026-10-20已完成一轮最终通过的真实厂商验收：12项配置用例通过，实际11次deepseek-flash文本请求及1次SenseVoiceSmall语音请求均HTTP200；8条提取案例的结构/引文8/8、预期待办6/6、关键原文11/11匹配。仅为团队合成开发集，不能当作真实机构准确率。过程和限制见[上传前验收](../ACCEPTANCE_2026-10-20.md)。

`tests/test_real_ai.py`默认跳过；普通回归不会调用收费或限流接口。`deploy/acceptance.py`在独立Linux临时目录运行完整回归、真实HTTP链路、依赖/Nginx模板检查，再显式启用`RUN_REAL_AI=1`。必须提供仅含合成内容的音频和服务器私有配置文件，密钥不放入参数或证据。运行方式见[部署说明](../deploy/README.md)。

12个验收用例包含8条合成提取案例、有效记忆/审批计划与当次意愿、交班摘要及质检、真实语音转写、缺失Key时返回503并保留人工录入。最后一例是故障注入，不调用厂商；其他用例合计正常产生11次DeepSeek文本请求和1次语音请求。记录HTTP状态、模型、耗时和原始合成输出；请求追踪只包裹真实网络调用，不替换厂商返回。临时存储与线上业务隔离，结果须人工复核。

下一步机构验证：由非开发者提供未见且去标识的独立案例，两人标注并解决分歧，冻结测试集与提示词版本；记录实际模型名、请求时间、延迟、失败与拒绝比例，保留原始输出；护理主管逐条核实漏项/误项/引用。对比原始记录流程，测每班记录和接班耗时、纠错次数、实际完成率；再询问至少数家目标机构的部署条件与付费意愿。未开展这些工作前，不填写虚构的省时比例、客户数或收入。
